# EUP-042 — Claim guest history after sign-up

| Field | Value |
|-------|-------|
| **Status** | Backlog |
| **Phase** | Phase 3 |
| **Labels** | `phase-3`, `feature` |

## Summary

Let logged-in users attach **legacy guest jury rows** to their account. Supports imported history ([EUP-043](EUP-043.md)) and guests who voted before creating an account.

Users pick from **all unclaimed** past identities (any nickname), not only their account display name — the group often uses nicknames or name variants.

## Acceptance criteria

- [ ] **Claim UI** (e.g. `/history/claim` or onboarding step): lists distinct unclaimed juror identities on **finished** parties (`participants.userId IS NULL`)
- [ ] Each identity shows: nickname, party count, optional expandable party list (year/title/code)
- [ ] User multi-selects every identity that was them (e.g. “Natalia”, “Nat”, “Natalia 🇪🇸”)
- [ ] Confirm step with clear warning: only claim your own votes
- [ ] On confirm: set `userId` on selected participant rows; votes unchanged
- [ ] Claimed parties appear in [EUP-024](EUP-024.md) history and personal [EUP-026](EUP-026.md) stats
- [ ] **First claim wins**: a participant row can link to at most one account; already-claimed rows hidden or disabled for others
- [ ] Empty state when nothing left to claim
- [ ] Link from History when user has zero linked parties but unclaimed data exists (optional prompt)

## Admin (minimal)

- [ ] Site admin can **unlink** a participant row (`userId → null`) for mistaken claims — admin-only API or internal tool

## Dependencies

- [EUP-005](EUP-005.md) — accounts
- [EUP-024](EUP-024.md) / [EUP-025](EUP-025.md) — history & replay
- [EUP-043](EUP-043.md) — imported parties (optional; same claim flow)

## Open questions (for product)

1. **Entry point** — one-time after first login, permanent nav link, or both?
2. **Nickname collision** — if two people shared “Alex”, is first-claim + admin unlink enough, or require party-by-party claim in v1?
3. **Notifications** — tell user when new import adds unclaimed rows they might want?

## Key decisions (locked)

- Match by **participant row claim**, not global unique display names
- Only **finished** parties; read-only link (no vote edits)
- Works for any nickname variant the user selects

## Notes

- Does not retroactively link by account display name alone
- Participant session cookie from an old browser is out of scope (optional future enhancement)
