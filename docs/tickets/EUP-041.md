# EUP-041 — Forgotten password reset

| Field | Value |
|-------|-------|
| **Status** | Done |
| **Phase** | Phase 3 |
| **Labels** | `phase-3`, `feature` |

## Summary

Let users who registered with email and password recover access when they forget their password.

## Acceptance criteria

- [x] “Forgot password?” link on login page
- [x] Request flow sends a time-limited reset link to the account email (reuse or extend Auth.js email provider)
- [x] Reset page sets a new password with validation (min length, confirmation field)
- [x] Token is single-use and expires (e.g. 1 hour)
- [x] Rate-limit reset requests per email to reduce abuse
- [x] Clear error when email is not registered (avoid leaking whether an account exists — optional product decision)
- [x] Document env requirements (`EMAIL_SERVER`, `EMAIL_FROM`) in auth deploy docs

## Dependencies

- [EUP-005](EUP-005.md) — email/password auth (done)
- Email delivery configured in production (`EMAIL_SERVER`, `EMAIL_FROM`)

## Notes

- Google-only accounts do not need password reset; hide or disable the flow when the user has no credentials provider.
- Magic-link login (Nodemailer provider) may overlap — decide whether reset replaces or complements magic link.
