## Summary

Define Drizzle schema and migrations for parties, entries, participants, votes, and results. **No users table in MVP** — nickname-only guests and host session token.

## Acceptance criteria

- [ ] Tables: `parties`, `party_entries`, `participants`, `votes`, `party_results`
- [ ] Party states: draft → lobby → voting_open → voting_closed → presenting → finished
- [ ] SQLite WAL mode enabled on connect
- [ ] Unique `(partyId, participantId)` on votes; unique nickname per party
- [ ] Vote allocations stored as JSON map `{ countryId: points }`
- [ ] Migrations applied via `pnpm db:push` / generate workflow

## Dependencies

- EUP-001

## Key decisions

- **Nickname-only MVP** — accounts deferred to Phase 2 (EUP-005).
- Host identified by **host session token**, not a user account.
