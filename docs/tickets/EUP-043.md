## Summary

Import ~**6 years** of past Eurovision voting nights from spreadsheets into finished parties so they appear in history, stats, and [EUP-042](EUP-042.md) claim flow.

Source format: tabular **country × jury** matrix (country rows, juror columns, cell = points that juror gave that country). Example header: `Hen`, `Jö`, `NL`, `Pav`, `TOTAL SCORE`; rows like `01 Estonia`, `12`, …

## Acceptance criteria

- [x] **Admin import** path (CLI script and/or `/admin` UI) — site admin only
- [x] Parse pasted or uploaded matrix (TSV / spreadsheet export); handle UTF-8 juror names (`Jö`, not `JÃ¶`)
- [x] Per import: **Eurovision year** (or party title), **juror nicknames**, country list + point grid
- [x] Build party: entries from country names, participants with `userId = null`, votes from inverted grid (each juror → `{ entryId: points }` allocations)
- [x] Validate Eurovision ballot rules per juror (each of 1,2,3,4,5,6,7,8,10,12 exactly once; ten scored countries)
- [x] Cross-check **TOTAL SCORE** column vs sum of jury columns (warn or reject on mismatch)
- [x] Set party `state = finished`, write `party_results` scoreboard snapshot (same shape as live ceremony)
- [x] Idempotent or explicit overwrite policy per year (document in import README)
- [x] Import docs with example file matching host’s spreadsheet layout

## Format assessment

**Yes, this layout can work.** It is the same information the app stores, just pivoted:

| Spreadsheet | App |
|-------------|-----|
| Column = juror | `participants.nickname` |
| Row = country | `party_entries` |
| Cell = points to country | one entry in `votes.allocationsJson` for that juror |

Importer **inverts** columns into per-juror ballots. Country names must map to [country catalog](../src/lib/countries/catalog.ts) (fuzzy match + admin preview for failures).

## Key decisions (locked)

- Imported participants start **unclaimed** (`userId = null`) until [EUP-042](EUP-042.md)
- Import creates **finished** parties only — no lobby/ceremony replay from import
