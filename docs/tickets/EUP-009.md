# EUP-009 — Real-time voting status

| Field | Value |
|-------|-------|
| **Status** | Done |
| **Phase** | MVP (Phase 1) |
| **Labels** | `mvp`, `feature` |

## Summary

Socket.io party rooms broadcast **who has voted** to all clients. Reconnect resync. Never broadcast point allocations during voting.

## Acceptance criteria

- [x] Join party room on connect with party id
- [x] `vote_submitted` / `voting_status` events update all clients
- [x] Reconnect restores participant vote status without leaking scores
- [x] Supports **8–10 simultaneous** connections in one party (smoke target)

## Implementation

- `src/lib/socket/party-events.ts` — event names and safe payload types
- `src/lib/socket/party-broadcast.ts` — build and emit `voting_status` / `vote_submitted`
- `server.ts` — `client:join_party` joins `party:{id}` room and sends full resync
- Vote submit, party state PATCH, and guest join API routes broadcast updates
- `src/hooks/use-party-socket.ts` + `party-lobby.tsx` — live jury checklist (no 5s polling)

## Dependencies

- EUP-008

## Key decisions

- Live checklist for **5–15 guest** parties on home LAN.
- Socket payloads expose `hasVoted` only; ballot allocations stay on authenticated HTTP routes.
